题面.md 必须交付可以直接渲染的 Markdown 正文。参考 example 中的题面，并按以下规则排版。
- 使用 `# 题目名称` 作为一级标题，使用 `## 题目描述`、`## 输入格式`、`## 输出格式` 等二级标题分节。数据范围放在 `## 数据范围` 或 `## 说明/提示` 中。标题、段落、列表和代码块之间留空行。
- 在正文、输入输出说明和数据范围中，变量、下标、区间、不等式和算式使用 `$...$` 包裹的 LaTeX 行内数学。具体写法如 `$T$`、`$a_i$`、`$a_1, a_2, \ldots, a_n$`、`$1 \le n \le 10^5$` 和 `$\sum n \le 10^5$`。需要单独展示的较长公式使用 `$$...$$`。
- 每组题面样例使用 `## 输入输出样例 #1` 这样的二级标题，下面用 `### 输入 #1`、`### 输出 #1` 分开。输入和输出各放在一对三反引号围栏中，原样保留每行数据和空格。
- 题面.md 的 JSON 字符串解码后应从 `# 题目名称` 开始，得到完整的 Markdown 正文。按 JSON 规则转义正文中的换行、引号和 LaTeX 反斜杠。

若原材料未规定是否有多组用例，且题目适合多组输入，尽量使用 T 表示用例数，并写清每组的数据范围和所有用例合计的数据限制。题面、题解、标程、生成器和校验器应遵循同一套约定。

题解.md 说明解题思路、正确性和时间与空间复杂度，并与 std.cpp 的实现一致。

std.cpp 从标准输入读取数据，向标准输出写出答案。valid.cpp 从标准输入读取数据，检查输入格式、数据范围及题面规定的其他约束。校验通过返回 0，失败时返回非零退出码。

gen.cpp 接收一个从 1 开始的测试点编号 i。每次运行完成以下步骤。
1. 生成第 i 个测试点的完整输入，保存为 data/i.in。
2. 运行 valid.exe，以 data/i.in 作为标准输入。校验通过后继续。
3. 运行 std.exe，以同一个 data/i.in 作为标准输入，将标准输出保存为 data/i.out。

gen.cpp 从题目目录运行，std.exe 和 valid.exe 已编译并位于同一目录。校验或运行失败时，报告测试点编号和失败步骤，并返回非零退出码。前几个编号复现题面样例，其他编号生成接近数据上限的大数据，并在大数据中覆盖关键边界和不同的合法结构。题面样例计入测试点总数。十组足以覆盖时共设计十组，需要更多时增加相应编号。题面样例的输出应与 std.cpp 对应的结果一致。
